# Reproducibility scope and experiment settings

The snapshot supports **archived-record reproduction** of reported figures, tables, and numerical claims, and **new reruns of individual selected frozen tasks**. These are different activities. The archive verifier reads saved scalar records, hashes, and the 221 reconstructed training-margin vectors; the figure builder reads scalar tables only. Neither evaluates a circuit or draws measurements. A staged rerun invokes the preserved scientific code with saved inputs and targets but creates a new measurement history. Neither operation is an independent rerun of the historical teacher generation and target calibration.

## Selected benchmark and fixed inputs

Each task is determined by a saved four-qubit teacher parameter array. Candidate teachers originally had independent standard-normal coordinates. They passed a 58,880-point noiseless signal screen and five earlier 1,000-forward-shot student fits; the first five passing candidates in seed order formed the five-teacher bank at each depth. The 300-candidate scalar audit, five-depth summary, and path-sanitized accepted 25-teacher registry are under `data/`; candidate seeds are under `configs/`. Three teachers were then **manually selected** per depth using archived validation and boosting-round summaries to include informative and difficult tasks. There was no recorded numerical ranking rule for this three-teacher choice, and the selected teachers were not sampled at random from the bank.

| Depth | Paper teachers 0, 1, 2 correspond to source IDs |
|---:|:---|
| 1 | 1, 2, 4 |
| 2 | 2, 3, 4 |
| 3 | 2, 3, 4 |
| 4 | 0, 1, 4 |
| 5 | 0, 1, 2 |

For each saved teacher, inputs were independently drawn from the uniform angle law on `[0, 2π]^4` and retained when the magnitude of its **exact noiseless** parity score was at least 0.2. Labels are the sign of that score. Each task has 1,536 training, 384 validation, and 1,024 held-out test examples. `data/teachers.csv` lists the selected seeds, realized class counts, split paths, and SHA-256 hashes. `datasets/` contains the exact arrays. The test split is packaged for independent evaluation; it did not define the targets or select checkpoints.

The student architecture begins at `|0000⟩`. Each of `d` layers applies per-qubit `RX, RY, RZ`, four ring `CZ` gates, and per-qubit `RX(x_q λ_{ℓ,q})`; a final local rotation block precedes global-Z parity measurement. The executed student initialization uses independent feature scales distributed as `N(1, 0.1²)` and local angles as `N(0, 0.1²)`. No post-update parameter projection was used. Frozen `src/boosting_qml` and campaign-specific `experiments/*/source` files retain the scientific implementation.

`targets/` contains the original full-precision target registries. The **margin target** is the median of five historical calibration models' unweighted `μ=0.1` empirical training-ramp losses, evaluated using exact `p=0` circuit means on the *same current training split*. Those calibration models were fitted at physical noise `p_1q=0.001`, `p_2q=0.01` with 1,000 forward shots. The **classification target** is the median of five separate historical `p=0` reference models' newly sampled 1,000-shot validation accuracies. A confirmed historical training-margin hit supplied a model; a nonhit supplied its terminal 500-epoch parameter state. The executed 25-shot validation check uses `ceil(384 × stored_accuracy)` with the stored binary64 value, not a cutoff reconstructed from a rounded percentage. In particular, the d1/paper-teacher-0 and d2/paper-teacher-0 cutoffs are 380 and 374 correct. `data/targets.csv` keeps both endpoint targets and their integer cutoffs; `data/margin_calibration_*.csv` and `data/classification_calibration.csv` retain the five contributing scalar results for every bank teacher.

## Executed training and reporting rules

The current fixed grid has 45 zero-physical-noise reference runs and 135 runs of each boosting method. For each selected task there are three prescribed repetitions; boosting uses `p_1q=p_2q` in `{0.005, 0.01, 0.02}`. The two endpoints share a training trajectory but have separately confirmed first hits and first-hit costs. A replacement attempt remains the same prescribed repetition. `run_specs/n25_runs.jsonl` records run IDs, paired initialization/order file hashes, seeds, targets, shot roles, and caps. The 45 reference runs are reused for the three projected PEC noise comparisons, not multiplied into 135 independent references.

Reference fitting, boosting fitting, edge, monitoring, and confirmation use 25 sampled forward shots **per evaluated circuit–input pair**. The loss is a Gaussian-smoothed hinge with `σ=0.5`, minibatch size 64, Optax Adam learning rate 0.01, and global gradient-norm clip 1. The reference uses an unweighted minibatch mean. Boosting weights are processed in float32: incoming weights are floored at `2^-52`, normalized over the complete training vector, floored again within each minibatch, then normalized within that minibatch; each minibatch loss is the weighted sum. A weak-fit epoch's patience statistic is the arithmetic mean of its 24 pre-update minibatch fitting losses. It is **not** a full-data weighted objective or a batch-mass-weighted epoch reduction.

The reference stops after 100 completed epochs without a strictly lower sampled epoch-mean fitting loss, with `min_delta=0` and best-parameter restoration, or at the 500-epoch cap. Weak fits use 20-epoch patience and the same upper cap. Boosting's separate outer stop uses 20 accepted rounds without more than `10^-5` improvement in an **exact noisy simulator-mean** full-training ramp, with at most 500 accepted rounds. The acquisition guard is 549,144,980 online raw shots. It is not a four-hour training stop. The fixed loss, parameter, seed, shot and stopping specifications are in the run JSONL and preserved frozen source.

The fitting loss is evaluated at a sampled score, but the backward circuit-mean derivative is supplied by the simulator: ideal mean for the reference and explicit PEC, noisy mean for boosting. Consequently `N_gradient=0` means **zero measured-gradient acquisitions**, not zero derivative computation. One 64-example fitting update uses 1,600 forward shots at `N=25`; a 1,536-example fitting epoch or one full-training edge acquisition uses 38,400. The plotted *algorithm shots* include completed fitting and once-counted edge acquisitions, plus actually measured-gradient shots (zero here), through the first independently confirmed hit. Monitoring, confirmation, post-fit diagnostics, and final evaluation are recorded separately. These roles can influence stopping or model selection, but are excluded from the primary algorithm-shot figure. The historical post-fit diagnostic acquisition remains a real historical expenditure even if future code omits it. The primary budget does not include hardware-compatible gradient estimation or the exact outer-mean computations.

For each method and endpoint separately, a teacher qualifies if at least two of its three prescribed runs independently confirm the target. Its resource is the median of **all successful first-hit algorithm costs**. A cell summary requires at least two qualifying teachers. A paired Projected-PEC/boosting ratio is formed within each jointly qualifying teacher, then summarized across teachers. One-teacher comparisons are labelled separately rather than treated as fully reportable cells. Nonhits, unresolved endpoints, and superseded attempts remain distinct in `data/resource_endpoints.csv` and associated scalar tables. An endpoint already confirmed is not relabelled unresolved merely because training continued for the other endpoint.

Projected PEC is the matched reference first-hit cost multiplied by the gatewise quasiprobability `γ²`; it has **no separately trained model or observed hit count**. The explicit Sampled-PEC campaign consists of eight configurations, with three teachers and three repetitions each (72 trajectories): `d3,p=.005,N=60`; `d2,p=.01,N=100`; `d3,p=.01,N=180`; `d1,p=.02,N=210`; `d2,p=.02,N=210`; `d3,p=.005,N=210`; `d3,p=.01,N=210`; `d3,p=.01,N=240`. These numbers are raw PEC shots per prediction. Never multiply their recorded costs by `γ²` a second time. `run_specs/explicit_pec_runs.jsonl`, `data/pec_runs.csv`, and `data/pec_all_methods.csv` retain all prescribed slots and selected terminal results. At `d3,p=.01`, repetitions 0 and 1 for each teacher in PEC180/210/240 share input and order arrays **across those PEC allocations** but differ from the corresponding N=25 reference arrays. These 18 slots are flagged `paired_n25_initial_and_order=false`; no cross-method initialization pairing should be claimed for them.

## What can be rerun

1. **Archived records and saved replay diagnostics:** `python scripts/verify_archive.py --snapshot . --output ../publication_verification/archive_check.json` and `python scripts/rebuild_figures.py --snapshot . --output ../publication_verification/paper_figures`. These need no quantum-circuit evaluations. The verifier checks receipt hashes, manuscript claims from saved scalars, and the reconstructed margin vectors; the figure script rebuilds scientific figures in a new directory outside this snapshot.
2. **Small training smoke:** `python scripts/smoke_test.py --output ../publication_verification/smoke` runs a tiny synthetic case. Its outputs are new diagnostic results, not a paper comparison cell.
3. **Selected-task rerun:** `python scripts/materialize_run.py --snapshot . --output-root ../publication_reruns --run-id <ID>` stages the paper-relevant N=25 frozen scientific source with saved task arrays, stream seeds, and targets. For PEC, use `--pec-slot <configuration> <paper-teacher> <repetition>`. The staging script prints a manual command; it does not launch training. This starts a fresh selected task even for a historically continued slot: inherited optimizer/checkpoint state and original campaign preflight are not recreated. The exported package removes only two personal Fashion-MNIST cache paths from an unrelated loader; both the source and adapted hashes are in the receipt. Repeat for the 315 N=25 and 72 PEC specification rows only after estimating required compute time, disk space and allocation. Results from such reruns must be reported separately from the archived figures.

The snapshot does **not constitute an independently runnable historical teacher-bank generation and full target-calibration pipeline**. It retains the accepted-bank registry, candidate screening scalars, calibration summaries, and selected task arrays, but not every original calibration run file, the exact consumed low-level margin fitter, or the complete historical binary environment. The margin-calibration consumed-input manifest identifies a low-level source revision that differs from the later available copy. An independent full-study rerun would need those validated materials and substantial new computation; no claim of full experimental reproduction follows from the included archive checks or one-run staging.

The canonical 315 N=25 selected-run records and 72 explicit PEC selected-run records are bundled as sanitized JSON/JSONL archives under `records/n25/` and `records/pec/`. The 46 available interrupted original N=25 attempts and five PEC source attempts for faithful continuations have their own archives under `records/superseded/` and `records/pec_precontinuation/`; none is counted as an extra repetition. `data/selected_run_record_index.csv` provides identities and original hashes. These records include scalar histories and outcome evidence, including terminal nonhits and failed weak-learner attempts where they were logged. All 633 confirmed N=25/PEC endpoint proof JSONs are archived separately, as are their first-hit checkpoints under `models/`. The archive does not contain every intermediate parameter state, the complete historical scheduler environment, or original target-calibration histories.

The selected-model four-stage bound study is a saved-model **replay diagnostic**. Its 221 model scalars and checks appear in `data/bound_stages.csv`, and the 1,748 regenerated weak-prediction vectors and their hashes are in `records/bound_replay_vectors.zip` and `data/bound_replay_vector_index.csv`. The 221 reconstructed ensemble training-margin vectors are retained separately in `records/reconstructed_training_margins.zip`; `data/bound_exponential_decomposition.csv` records each vector’s above- and at/below-margin contributions to the exponential gap. The original per-example edge vectors had been discarded. Agreement with edges, coefficients, weights, and cached scalar losses corroborates the replay, but does not bitwise certify the original sampled vectors. The retrospective 57-run Real AdaBoost round-count figure is a different cohort/rule from the 221-model bound analysis. Neither is a prospective prediction of future rounds.

## Training or changing the model

To train an unchanged selected task, first install the requirements as shown in `README.md`. Then run `scripts/materialize_run.py` with one ID from `run_specs/n25_runs.jsonl`, or one configuration, paper-teacher index, and repetition from `run_specs/explicit_pec_runs.jsonl`. The script copies the corresponding frozen runner, package source, fixed inputs, and target values into a **new directory outside this repository**. It prints a `manual_training_command`; inspect the staged manifest and run that command to start training. The command may take substantial time and draws new measurement samples. It is a new run, not a continuation or exact replay of the archived result. The staging script refuses to overwrite a previous run directory.

To test a changed method, use a new branch and a new experiment identity:

```bash
git switch -c study/my-change
PYTHONPATH=src python -m pytest -q tests/test_publication_protocol.py
python scripts/smoke_test.py --output ../my_change/smoke
```

The small fit in `scripts/smoke_test.py` shows how to construct a PQC learner and call `fit_weighted`. The circuit and noise implementations are under `src/boosting_qml/pqc/`; the two boosting algorithms are under `src/boosting_qml/boosting/`; explicit PEC sampling is under `src/boosting_qml/pec/explicit_gatewise.py`. For a changed full experiment, create a new runner and manifest from the relevant `experiments/` example, record the changed source commit, all model and training settings, task and split hashes, initialization and sampling seeds, shot allocation, stopping rules, and acquisition costs. Write its outputs outside the publication repository, using run IDs that cannot be confused with the paper's saved IDs. The supplied `materialize_run.py` only stages the fixed paper protocols; editing its staged files would invalidate their recorded source hashes and is not a supported way to start a changed protocol.

Select models using training and validation data, then evaluate the held-out test split only after the selection is fixed. Keep new figures, hit counts, and costs separate from the archived tables; changing a method or target creates a new study, not a correction to a historical run. If you change a source file in this repository, `scripts/verify_archive.py` will correctly report a receipt-hash mismatch until the changed work is documented as a new version. Do not update the receipt merely to present new code as the code used for the paper's saved results.
